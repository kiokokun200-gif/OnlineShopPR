Нужно сделать небольшой маркетплейс.

Проект должен состоять из трёх основных частей:

база данных в третьей нормальной форме;

рабочее API;

WPF-приложение.

Пользователь должен иметь возможность зарегистрироваться и войти в аккаунт.

При регистрации он вводит логин, пароль и повторяет пароль ещё раз. Пароль нельзя хранить в базе данных обычным текстом, его нужно хранить в виде хеша.

Товары можно смотреть без регистрации. Гость должен иметь возможность открыть каталог, посмотреть информацию о товаре, выполнить поиск и использовать фильтры.

После авторизации пользователь получает дополнительные возможности.

У каждого товара должны быть:

название;

цена;

описание;

категория;

фотография;

оценка;

количество товара на складе;

количество штук в упаковке, если это необходимо;

признак, доступен товар для покупки или нет.

Фотографии товаров пока хранятся прямо в проекте. В базе данных можно хранить только название файла или путь к изображению.

Товары должны быть разделены по категориям.

Нужно сделать поиск по названию товара и фильтрацию хотя бы по категории и цене.

Если товара нет на складе или администратор сделал его недоступным, купить его нельзя.

Пользователь может добавлять товары в корзину.

В корзине нужно показывать:

товары;

их количество;

цену;

общую стоимость.

Количество товара в корзине можно изменять. Также товар можно удалить из корзины.

Покупку можно оформить двумя способами:

купить один товар сразу;

оформить все товары из корзины.

При оформлении заказа пользователь выбирает способ получения.

Если стоимость заказа меньше 600 рублей, доступен только самовывоз из ПВЗ.

Если стоимость заказа больше 600 рублей, пользователь может выбрать доставку по адресу или самовывоз.

Для доставки нужно указать адрес.

Для самовывоза пользователь выбирает один из существующих ПВЗ.

Список ПВЗ должен храниться в базе данных.

После оформления создаётся заказ.

У заказа должны храниться:

дата оформления;

пользователь;

список товаров;

количество товаров;

цена товаров на момент покупки;

итоговая стоимость;

способ получения;

адрес доставки или выбранный ПВЗ;

статус заказа.

Пример статусов:

Оформлен;

В обработке;

Передан в доставку;

Готов к выдаче;

Получен;

Отменён.

Важно: если цена товара позже изменится, старые заказы не должны изменяться. В заказе должна оставаться цена, которая была на момент покупки.

Пользователь должен иметь возможность посмотреть историю своих заказов.

Историю можно сортировать по дате:

сначала новые;

сначала старые.

При открытии заказа пользователь должен видеть все товары, их количество, цену и итоговую сумму.

Также нужно сделать избранное.

Пользователь может добавить товар в избранное, удалить его оттуда или перенести в корзину.

Нужно добавить отзывы и оценки.

Только авторизованный пользователь может поставить товару оценку и написать отзыв.

Все пользователи могут читать отзывы.

Средняя оценка товара должна рассчитываться на основе всех оценок пользователей.

Также нужен администратор.

Администратор может:

добавлять товары;

редактировать товары;

менять цену;

менять описание;

менять категорию;

менять изображение;

менять количество товара на складе;

делать товар доступным или недоступным для покупки;

добавлять и редактировать категории;

управлять ПВЗ;

просматривать заказы;

менять статус заказа;

удалять некорректные отзывы.

В системе должны быть три типа пользователей:

гость;

обычный пользователь;

администратор.

Гость может смотреть товары, искать их, использовать фильтры и читать отзывы.

Обычный пользователь дополнительно может пользоваться корзиной, избранным, оформлять заказы, смотреть историю и оставлять отзывы.

Администратор управляет товарами, категориями, ПВЗ, заказами и отзывами.

Проект выполняют три человека.

Работу нужно разделить так, чтобы у каждого была своя полноценная часть.

Например:

Первый студент может заниматься базой данных, API, авторизацией и логикой заказов.

Второй студент может заниматься WPF-приложением, каталогом, корзиной, избранным, историей заказов и интерфейсом администратора.

Распределение можно изменить, но на защите каждый должен уметь показать и объяснить свою часть проекта.
